# Response to the 2026-08-24 design review

**Reviewed document:** [2026-08-24-codex-design-review.md](2026-08-24-codex-design-review.md)
**日本語版:** [2026-08-24-codex-design-review.ja.md](2026-08-24-codex-design-review.ja.md)

The review's central finding was correct and worth stating plainly: the privacy
guarantee failed open. Names and addresses escaped when Gemma was unavailable, a
failed leak check did not stop a release, caller-controlled placeholders formed a
rehydration oracle, and rehydrated PII was persisted indefinitely outside the
TTL-protected vault. Each of those is now closed.

The rest of this document records what changed, and — as importantly — what we
decided not to do and why.

## The governing decision: cut scope, then fail closed

The review offered a choice on the vault: fix concurrency and expiry properly
(8–12 h), or cut shared sessions (2–3 h). We cut, and cut further than asked.

There is now **one server-generated request id per request**, minted by the
gateway as a UUIDv7 and used as the vault key. `POST /v1/ask` accepts only
`{text}`. A body carrying `session_id` is rejected with 400 rather than silently
ignored, because a caller who believes they chose a vault key and did not is worse
off than one told plainly they cannot. The inbound `X-Request-ID` header is
echoed for correlation but never adopted — it is the vault key, and a caller who
could choose it could name another request's mapping.

That single change removes the cross-session oracle, the concurrency race, the
expiry-restart collision, and the multi-turn linkage risk at once. Placeholder
stability across turns is gone with it; that is a real capability loss, and the
right trade for a submission.

## §2 — trust-boundary weaknesses

| Weakness                                                  | What we did                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Gemma span extraction fails open**                      | Extraction now returns a discriminated `valid-empty \| valid-spans \| invalid`. An empty list is only believed when the model actually said `{"spans": []}`; a malformed, fenced-but-broken, or argued-away answer is `invalid` and the request returns 502 without ever reaching Core. Temperature is 0, untrusted input is wrapped in `<<<INPUT … INPUT>>>` delimiters that are stripped from the input first, and the instruction states that the delimited text is data and never a command. Tests cover prompt injection, Japanese and English names and addresses, and the empty-vs-unusable distinction. |
| **Caller-controlled sessions and literal placeholders**   | Sessions removed (above). Literal `⟦` or `⟧` in raw input is a 400 before masking and before any vault write — a half-open probe counts too. Synthesis is handed the tokenizer's own allocation list and the vault generation, never a token set re-derived from the prompt: a placeholder echoed into a caller's own prompt text is not thereby trusted.                                                                                                                                                                                                                                                       |
| **Typed placeholders do not prevent reconstruction**      | Renamed throughout: the mechanism is **pseudonymization**, not anonymization. The residual risk — category disclosure, equality disclosure, and surviving quasi-identifiers — is stated in `knowledge/policies/pii-masking.md` and in ARCHITECTURE rather than left implicit. The semantic gate is the Gemma judge, now applied as a fail-closed veto (below). We did **not** move to per-request HMAC-bound tokens; with one vault per request the cross-request linkage they defend against no longer exists, and the category prefix is load-bearing for the demo's legibility.                              |
| **Failed attestation does not gate release**              | The pipeline now stops before rehydration on any failed gate and throws `ReleaseRefusedError`. Nothing is rehydrated, nothing is returned, and the persisted record contains no Core body in released form. The refusal carries category names only.                                                                                                                                                                                                                                                                                                                                                            |
| **Vault concurrency and expiry**                          | Cut to one entry per request (above), plus a `generation` counter checked at rehydration and Firestore `runTransaction` for allocation. The in-memory and Firestore implementations were made consistent so a local run and a deployed run behave the same.                                                                                                                                                                                                                                                                                                                                                     |
| **Missing or expired vault data still produced `stable`** | Missing mapping → 409, expired → 410, generation mismatch → 409, unresolved token → 409, invented token → 409. None of them produce a final answer.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **The Gemma judge is security-inert**                     | Now **asymmetric**: `leak: true` or no usable verdict blocks the release (422); `leak: false` adds no trust at all. A probabilistic model may veto; it may never vouch. Generation is deterministic (temperature 0, top_p 1) and it is labelled probabilistic in the code, the docs and the UI. The UI can no longer show "PASS" and "Gemma flagged" together, because a flag means there is no answer to show.                                                                                                                                                                                                 |
| **Rehydrated PII persisted indefinitely**                 | Firestore now stores only masked artifacts keyed by `request_id`: the masked prompt, Core's tokenized response, the OKF document (whose body holds the _masked_ answer), hashes, and `expires_at`. The rehydrated answer exists in one API response and nowhere else. The store enforces expiry in the application as well as by TTL policy, because a TTL sweep lags by minutes.                                                                                                                                                                                                                               |
| **"Human-reviewed" is forgeable**                         | Removed. See below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Logs and traces can contain unstructured PII**          | Recursive scrubbing replaced by a **typed allowlist**. Only named fields are emitted at all — hashes, counts, enums, internal UUIDs — and anything else is dropped, with the dropped key _names_ recorded under `dropped_fields` so a developer sees the omission instead of debugging a silent one. `errorFields()` no longer emits `error_message`; spans record `error.class` and `error.code` and never call `recordException`, which copies the exception message and stack verbatim. The rationale is that the old scrubber ran the tokenizer's regexes, which have no PERSON or ADDRESS pattern at all.  |
| **No output disclosure policy**                           | `API_KEY`, `AWS_KEY`, `JWT`, `CREDIT_CARD` and `MY_NUMBER` are never restored into a released answer by default. The placeholder stays, and the withheld categories appear in `attestation.withheld` in both the API response and the OKF document. `REHYDRATE_ALLOW_CATEGORIES` re-enables specific categories for a deployment with a stated purpose.                                                                                                                                                                                                                                                         |
| **Cost and storage abuse**                                | Body limit cut from 10 MB to 64 KB, a single 60 s end-to-end deadline across the whole chain, and a demo-grade per-IP rate limit (default 20/min, `0` disables). All three are env-configurable.                                                                                                                                                                                                                                                                                                                                                                                                                |

## Human approval: removed, and why

The review's suggestion was "remove, or derive the reviewer from verified
IAP/OIDC claims". We removed it — the routes, the UI button, the config key, the
client command, the tests and the documentation.

The reason is worth recording, because it is not "we ran out of time". The public
gateway authenticates nobody. There is no principal to name, so a `human:<id>`
actor minted from a click is a claim about a person who was never identified —
and under OKF §5.3 that claim is exactly what raises a document to
_human-reviewed_. Emitting it would not be a weak signal; it would be a false one,
and it would devalue the tier for every consumer that reads the document.

The trust-tier derivation itself stays generic in `packages/common/src/okf.ts`.
OKF is a general format and other consumers do have authenticated reviewers. This
product simply never mints a `human:` actor, and the UI reports **review identity:
none**, always, as one of four separate dimensions rather than as an absence the
reader has to infer.

## §3 — OKF v0.2

Every material defect the review listed is addressed.

1. **Generator attribution.** `generated.by` is now `synthesis_agent/<version>`.
   Synthesis assembles the concept; §7 attributes a document to whoever wrote it.
2. **Core as provenance.** The Core invocation is a `sources[]` entry —
   `core-response`, `resource: /requests/<id>/core-response.md`,
   `author: core_agent/<GEMINI_MODEL>` — alongside `masked-prompt` and
   `pii-policy`.
3. **Verifier attribution.** `verified[].by` is
   `process:leak-check@<attester sha256 short>`. TypeScript regex code decides the
   verdict; Gemma only ever advises, so naming a Gemma model as the verifier was
   simply wrong. The body now says "leak-policy check", not "verified", and states
   that it is not a factual validation of the answer.
4. **Provenance no longer dangles.** `/v1/requests/:id/masked-prompt.md` and
   `/v1/requests/:id/core-response.md` are real routes serving the stored masked
   artifacts, and `GET /v1/requests/:id` serves the evidence document itself.
5. **The attester resolves.** `knowledge/references/attesters/leak_check.ts` is a
   byte-identical copy of the module Synthesis imports, and
   `packages/common/test/attester_bundle.test.ts` fails if their SHA-256 digests
   diverge. A judge can follow `attester.resource` and run the file; a reader can
   confirm from `attestation.attester_sha256` which bytes produced their verdict.
   We chose copy-plus-test over a `paths` mapping because TypeScript's `rootDir`
   will not compile a source file from outside the package tree, and a bundle
   whose sanctioned attester cannot be executed is not attestable.
6. **The receipt contract is complete.** `executor.receipt` and what `verify()`
   demands are now the same five fields — `request_id`, `masked_prompt_hash`,
   `response_hash`, `findings`, `response` — exported from the attester as
   `RECEIPT_FIELDS` and asserted equal in a test. `masked_prompt_hash` is new: it
   binds a verdict to the exact exchange that produced it, so a receipt cannot be
   replayed as evidence for another.
7. **Machine-readable evidence is persisted.** A top-level `attestation:` block
   carries `computation`, `computation_sha256`, `attester_sha256`,
   `masked_prompt_sha256`, `core_response_sha256`, `verdict`, `checked_at`,
   `request_id`, `trace_id` and `withheld`.
8. **Malformed trust metadata fails closed.** A `verified` entry without a string
   `by` names nobody and no longer votes, so `verified: [{}]` derives
   _unverified_. An absent or unparseable `stale_after` derives freshness
   `unknown`, never `fresh`; `isStale()` treats `unknown` as stale so a caller
   asking the yes/no question fails closed. The malformed value itself is still
   preserved in the document (§11).
9. **"Signed" is gone.** There is no signature and no MAC, so the word does not
   appear. A test asserts it never reappears in a generated document. Same for
   "append-only" (the record is a per-request document with a TTL), "never leaks",
   and "all PII".
10. **Bundle drift fixed.** `knowledge/computations/index.md` says `typescript`
    and describes the pre-rehydration check. `knowledge/log.md` uses the reserved
    exact-date heading.

**Replay.** `just verify-answer <request_id>` fetches the evidence document and
both masked sources, re-derives the leak-check verdict with an _independently
transcribed_ scanner in `clients/python/pgw.py`, and compares every recorded
digest. It deliberately does not import the fleet's own attester: a replay that
did would only prove the fleet agrees with itself.

## Tests

424 unit and integration tests pass, up from 295, and 16 Playwright specs (up from 9). The adversarial cases added:

- extraction prompt injection, and a caller who writes the `<<<INPUT` delimiters
- the `valid-empty` / `invalid` distinction, so "unusable" is never read as "clean"
- Japanese and English name and address spans
- a semantic name leak from a mocked Core, caught by the judge veto with the
  deterministic scanner passing
- literal `⟦…⟧` placeholders in raw input, including a half-open probe
- a body carrying `session_id`
- an inbound `X-Request-ID` that must not become the vault key
- missing, expired and generation-mismatched vault mappings
- an invented token, and a token echoed into the prompt that must not become trusted
- a failed release persisting no body and returning no answer
- withheld categories left masked, and released when explicitly allowed
- log fields dropped rather than masked, and exception messages absent from logs
  and spans
- rate limit, oversized body, and the response-schema contract the UI relies on

The Playwright specs were rewritten to drive the new UI: four separate dimensions,
a blocked-request panel, no approve button, and the masked evidence routes.

## What we deliberately did not do

- **Cloud KMS-signed attestation envelopes.** The review calls them optional. The
  digests plus a replayable command deliver the property that matters — a reader
  can re-derive the verdict — without a key-management story we cannot operate in
  the remaining week.
- **Per-request HMAC-bound tokens.** With one vault per request, the cross-request
  linkage they defend against does not exist. The category prefix stays because it
  is what makes the masked prompt legible in the demo, and its disclosure is now
  documented rather than denied.
- **Authenticated human review.** Out of scope, for the reason given above. It is
  a post-submission item.
- **Making the Synthesis A2A surface execute its advertised skill.** Instead the
  Agent Card was corrected: it now says it acknowledges an exchange, and that leak
  checking, release and OKF assembly run on the HTTP routes. An accurate card is
  better than a hastily-built duplicate path.
- **Hash-chained audit records.** Nice-to-have, and in tension with a TTL policy
  that deletes records.
